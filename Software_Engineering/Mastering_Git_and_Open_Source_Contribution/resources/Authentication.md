# Git Authentication

Before you can clone repositories, push commits, or perform other actions on GitHub, you need to authenticate your identity. Authentication helps protect your account and repositories from unauthorized access.

GitHub supports several authentication methods, but the three most common are:

1. Username and password with Two-Factor Authentication (2FA) or a Passkey
2. Personal Access Token (PAT)
3. SSH Key

---

# Username and Password with Two-Factor Authentication (2FA) or Passkey

This is the standard authentication method used when signing in to the GitHub website. While you can log in to GitHub using your username and password, Git operations over HTTPS now require a Personal Access Token instead of your password.

## Two-Factor Authentication (2FA)

Two-Factor Authentication adds an extra layer of security to your GitHub account.

With 2FA enabled, logging in requires:

- Your GitHub username
- Your password
- A verification code generated by an authenticator app or sent to your device

Even if someone knows your password, they won't be able to access your account without the verification code.

---

## Passkey

A passkey is a modern authentication method that lets you sign in without entering a password.

Instead of remembering passwords, your device securely stores a digital credential that can be used to verify your identity.

After registering a passkey with GitHub, you can simply approve the login request using your device's biometric authentication or screen lock.

---

# Personal Access Token (PAT)

A Personal Access Token (PAT) is a secure alternative to using your GitHub password when performing Git operations over HTTPS.

A PAT works like a password, but you can control exactly what permissions it has. For example, you can create a token that only has permission to access repositories without granting unnecessary privileges.

---

## Creating a Personal Access Token

To generate a new PAT:

1. Open **GitHub Settings**.
2. Navigate to **Developer Settings**.
3. Select **Personal Access Tokens**.
4. Click **Generate new token**.
5. Give your token a descriptive name.
6. Choose an expiration date.
7. Select the permissions (scopes) your token should have.
8. Click **Generate token**.

GitHub will display the token only once, so make sure you copy it immediately and store it somewhere safe.

> **Important:** Never share your Personal Access Token or upload it to a public repository.

---

## Using a PAT with Git

Clone a repository using HTTPS:

```bash
git clone https://github.com/<username>/<repository>.git
```

When Git prompts for authentication:

- Enter your **GitHub username** as the username.
- Paste your **Personal Access Token** instead of your GitHub password.

For example:

```bash
git clone https://github.com/betascribbles/my-repo-001.git
```

Git will ask for your credentials during the cloning process.

---

## Pushing Changes with a PAT

After making your changes, push them normally:

```bash
git add .
git commit -m "Meaningful commit message"
git push origin main
```

If Git requests authentication, enter:

- Your GitHub username
- Your Personal Access Token as the password

Once your credentials are saved by Git Credential Manager, you usually won't need to enter them again.

---

# SSH Key Authentication

SSH authentication allows you to connect to GitHub without typing your username and password every time.

Instead, GitHub verifies your identity using a pair of cryptographic keys:

- **Public Key** – Uploaded to GitHub.
- **Private Key** – Stored securely on your computer and should never be shared.

Once SSH is configured, Git automatically authenticates you whenever you interact with GitHub.

---

## Generate an SSH Key

Open your terminal and run:

```bash
ssh-keygen -t ed25519 -C "your_email@example.com"
```

Follow the prompts:

1. Press **Enter** to save the key in the default location.
2. Optionally enter a passphrase for additional security.

After the process finishes, you'll have two files:

- `~/.ssh/id_ed25519` → Private Key
- `~/.ssh/id_ed25519.pub` → Public Key

Keep your private key secure and never share it with anyone.

---

## Add Your SSH Key to GitHub

After generating the key:

1. Open your GitHub account.
2. Go to **Settings** → **SSH and GPG Keys**.
3. Click **New SSH Key**.
4. Open your public key:

```bash
cat ~/.ssh/id_ed25519.pub
```

5. Copy the entire output.
6. Paste it into GitHub.
7. Click **Add SSH Key**.

Your GitHub account is now linked to your computer through SSH authentication.

---

## Clone a Repository Using SSH

Instead of using an HTTPS URL, use the SSH URL provided by GitHub:

```bash
git clone git@github.com:username/repository.git
```

Example:

```bash
git clone git@github.com:betascribbles/my-repo-001.git
```

---

## Push Changes Using SSH

Once the repository is cloned through SSH, pushing changes is exactly the same as before:

```bash
git add .
git commit -m "Add new feature"
git push origin main
```

Since SSH handles authentication automatically, Git won't ask for your username or password every time you push.

---

# Which Authentication Method Should You Use?

Each authentication method has its own use case:

| Method | Best For |
|---------|----------|
| **Username & Password + 2FA** | Logging into the GitHub website |
| **Personal Access Token (PAT)** | Git operations over HTTPS and third-party applications |
| **SSH Key** | Frequent Git usage from your local machine without repeatedly entering credentials |

For most developers, **SSH keys** provide the most convenient experience for everyday development, while **Personal Access Tokens** are commonly used when working over HTTPS or integrating with external tools.
